# 插件利用、视觉与边界审计

本页回答两个问题：每个第三方插件为什么存在，以及它是否会与原创 RPG 的唯一状态发生冲突。原则是基础设施优先复用成熟项目，玩法数据只由自研插件拥有；没有明确消费者的插件不预装。

## 社区插件保留结论

| 插件 | 实际消费者 | 最终用途 | 决策与边界 |
|---|---|---|---|
| LuckPerms | 管理员、`RpgIntegrations` | 权限组、职业/分支/转数动态 context | 保留。单服使用 SQLite，避免 H2 JVM 关服钩子告警；原创插件只提供 context，不把职业复制成永久权限组；多服再迁移 PostgreSQL |
| PlaceholderAPI | `RpgIntegrations`、后续计分板/网站展示 | 38 个 `%sivita_*%` 内部占位符入参分支 | 保留。禁用 expansion cloud；回调只读内存快照，不发起 JDBC |
| AuthMeReloaded | 离线模式登录边界 | 配置阶段中英 Dialog、注册、登录、登录前冻结与命令白名单 | 保留。`online-mode=false` 时必需；不启用付费账号识别，不接管 RPG 档案。取消 pre-join 直接断开，不再进入世界叠加第二个窗口；自动 IP 会话关闭，公网入口仍须补 pre-join 失败限速 |
| WorldEdit | 建筑管理员 | 出生点、活动区和后续手工副本模板制作 | 保留为管理工具。编辑量、历史和半径有限制；不参与运行时副本复制 |
| WorldGuard | 管理员、`RpgHub`、公共世界 | 主城/活动区/建筑区保护 | 保留。`RpgHub` 创建 48 边形 `sivita_hub` 区域，使保护范围与地图圆形边界一致；自研监听器仍覆盖爆炸、火焰、活塞、NPC 伤害等边界 |
| Chunky | 运维人员 | 三个持久原版世界的边界内预生成 | 保留。任务可重启恢复；不强制加载已生成区块，不对动态副本世界运行 |
| squaremap | 官网 `/map/`、玩家 | 主城导览与三个持久原版世界的低频网页地图 | 保留。独立主城公开安全区和 11 个服务 NPC 地标；动态 `dungeon_instance_*` 继续禁用。全地图隐藏玩家、资源与隐藏内容，并使用单渲染线程 |
| SkinsRestorer | 离线登录玩家、资源包加载流程、LuckPerms | 名称皮肤的获取、缓存、加入时应用与资源包后重应用 | 保留。15.12.5 原生支持 26.2；默认中文并按客户端语言切换。只开放本人 set/update/clear，URL、代改、推荐 GUI、头颅和管理命令拒绝，不拥有 RPG 外观或装备模型 |
| Citizens2 | `RpgStory`、BetonQuest | 少量动态演员、寻路、跟随和护送 | 保留。固定柜台不迁移；私有演员仅对任务本人可见，总并发 12，路径搜索与视觉效果服从负载降级 |
| BetonQuest | `RpgStory`、内容配置 | 中英文分支对白、章节标签和内容包 | 保留。仅注册 `sivita_story_begin/claim/eligible` 白名单组件；脚本不能执行任意控制台命令或直接结算核心奖励 |
| GriefPrevention | 原版主世界生存玩家 | 领地、容器、动物、红石与信任分级 | 保留。仅 `world` 可圈地；主城、下界、末地和动态副本禁用。初始 256 格、有效在线每小时 64 格、上限 20000、最多 8 块；关闭箱子自动圈地、金币买卖面积、PvP 和攻城 |
| EssentialsX Core | 全体玩家、管理员、`RpgEssentials` | 私信、回复、屏蔽、邮件、AFK、在线列表、延迟、规则、查询与受控 TPA | 保留上游 Core，不装 Spawn/Chat/Protect/AntiBuild。`home/back/spawn/wild`、经济、礼包、商店、修理和昵称入口全部禁用；命名空间与 `e*` 绕过由桥接层拦截。TPA 在任一方战斗或副本内拒绝 |
| MyPet | `RpgPets` | 生存捕获、真实实体 AI、等级、四条培养路线、旅囊与最多四只存储 | 保留为成熟宠物引擎。普通玩家统一从 `/companion` 进入；原生商店/交易、自动拾取、挖矿、伐木、钓鱼和动物产物关闭。玩家 PvP、主城/副本出战、单击伤害与单次经验均有硬上限；只攻击敌怪且直接伤害保留 1 点生命，持续效果越界击杀不掉落；复苏只走 `RpgCore` 金币流水 |
| BetterModel | `RpgMobs` | 经审核的稀有怪完整骨骼模型与动画 | 保留、纯表现。读取 `.bbmodel` 并生成资源包资产；原 Bukkit 实体仍独占 AI、碰撞、伤害和掉落。普通怪不套模型；压力档最多 20 个，严重档关闭并完整回退原版实体 |

PacketEvents 已从锁文件移除。2.13.0 虽然明确支持 26.2，但当前只有未向普通玩家开放的 MyPet 单独音量滑块会用到它；AuthMe 的登录背包保护、登录前补全、正版绕过与 BetonQuest 数据包对话均关闭，核心登录限制不依赖它。为隐藏选项预装协议注入层会扩大升级、兼容和数据包故障面。Vault、MythicMobs、MMOItems、Oraxen、菜单框架同样不引入：经济、怪物、装备和菜单已经有唯一自研实现，接入第二套状态会产生绕过绑定、重复结算或版本锁定。怪物模型例外地复用 BetterModel，但它被严格限制为无结算权的完整身体表现适配层。2026-08-07 已复核 MythicMobs 5.13.0：免费发行支持 26.2，但免费不等于适合作为唯一基础设施；它会引入第二套怪物模板、技能、生成与掉落真相，因此当前继续由 `rpg-mobs` 统一等级、属性、词缀、掉落和负载降级。

QuickShop-Hikari、Shopkeepers 和通用面对面交易插件也不加入。它们都是成熟方案，但前两者会增加第二套箱子/NPC 商店状态，面对面交易则会让高价值物品绕过手续费、绑定、唯一物品索引、审计与持久化邮箱。普通原版日用品仍可用原版容器或丢弃交换；高价值物品统一进入 `rpg-market`。完整矩阵见 [插件必要性](PLUGIN_NECESSITY.md)。

## 自研插件的唯一所有权

- `RpgCore` 是角色、体力、财富、市场/商人账本、技能和副本入场预留的唯一数据库边界。
- `RpgItems` 的签名 schema 3 是装备身份唯一来源；资源包模型、Lore 或第三方 NBT 不能证明装备有效。
- `RpgCombat` 是职业、装备、处决与 Boss/PvP 缩放的最终伤害总线，并向主城、床家园和后续导航暴露同一份持久战斗状态。
- `RpgDungeons` 独占实例、队伍、波次和参与者奖励；WorldEdit 只用于制作内容，不拥有 session。
- `RpgGuide` 使用原生 Paper Inventory API，避免通用菜单插件在高频重载、异步占位符和物品拖拽上引入另一套事件规则。
- `RpgHub` 只拥有主城方块、NPC 入口、保护和交通。`/home` 直接复用玩家的原版主世界床重生点；`/back` 只持久保存上一次受控交通或非副本死亡位置，并复用战斗锁、副本隔离和预生成区块检查。NPC 通过 `GuideMenuService` 打开可信菜单，不复制职业、装备、货币或副本状态。
- `RpgAiNpc` 只有公开规则解释权；外部模型无工具、无写服务引用，失败时使用本地知识库。线程、限流和职责边界见 [NPC 架构](NPC.md)。
- `RpgCosmetics` 只拥有玩家选择的非战斗共鸣外观、鞘翅轨迹和受预算约束的一次性庆祝；不改属性、不决定技能命中，也不覆盖 Boss 预警。设计见 [共鸣外观](COSMETICS.md)，旧 `zypec/Particles` 的兼容与线程审计见 [专页](PARTICLES_AUDIT.md)。
- `RpgStory` 是 Citizens 与 BetonQuest 进入核心玩法的唯一白名单桥；它拥有演员会话、容量保护和一次性奖励键，不拥有角色、装备或货币余额。
- `RpgMobs` 独占怪物等级、词缀、掉落与模型分配；BetterModel 只拿到实体引用生成客户端外壳，负载严重时外壳全部关闭，玩法不变。
- `RpgCommunity` 拥有社群、邀请、师徒契约、周建设与排行榜；不把单个活动或商店页再拆成插件。
- `RpgEssentials` 只限定 EssentialsX 的命令和 TPA 边界，不建立第二套家园、经济、出生点或礼包状态。
- `RpgPets` 拥有玩家入口、捕获世界、金币复苏流水、伤害/经验上限、PvP/副本限制和经济防刷；MyPet 只拥有宠物实体、AI、等级技能树与持久化，不接触服务器账本。

## 菜单视觉语言

入口采用四层互补而不是四套菜单状态：26.2 原生 `#minecraft:quick_actions` 让玩家按默认 `G` 打开低频快捷操作；旅者罗盘右键适合刚加入和不熟悉按键的玩家；`/menu` 是任何客户端都能使用的兜底；NPC 只打开当前场景最相关的页面。快捷操作**计划**由数据包 `sivita-navigation` 提供，按钮文本使用资源包翻译键随客户端语言切换。**待办（G-206）**：该数据包目录与部署脚本 `server/bin/verify-installation.sh` 当前都不在本仓库内（`server/` 目录被 `.gitignore` 排除），因此 `#minecraft:quick_actions` 入口在版本控制下不可审计，`docs/RESOURCE_PACK_QA.md` 对 `verify-installation.sh` 的硬依赖也无法在本仓验证。建议后续任务把数据包与安装校验脚本纳入版本控制（或用脚本生成 + 校验替代），属于代码改动，不在本次文档订正范围内。复杂选择仍由自研 Inventory GUI 完成，所有点击最终回到同一命令与事务校验。钟表不被强制占用，因为它会长期挤占生存快捷栏；也不安装通用菜单框架。

所有菜单遵循同一语义，不用随机材料凑图标：

| 颜色/图标 | 含义 |
|---|---|
| 青色、锻造核心 | 可成长、可操作、装备生产 |
| 绿色、治疗/勾选 | 已完成、恢复、可安全领取 |
| 金色、门票/核心 | 副本、稀有入口、需要确认的价值操作 |
| 紫色、技能书/异变核心 | 技能、变异、跨职业构筑 |
| 红色、屏障/血月精华 | 销毁、危险、失败或世界威胁 |
| 灰色 | 未满足条件或纯说明，不可点击 |

主菜单按“当前旅程、角色成长、冒险探索、经济循环、社群服务”分层，技能页固定呈现基础、进阶与两条分支，并在说明中写明实际效果、法力、冷却和装配方式。技能菜单只负责学习、连续升级、查看和装配：左键装入当前槽，菜单内数字 1–4 可选指定槽，右键升级；战斗中手持自制武器时单按 `F` 施放当前技能、双按 `F` 切换。技能监听只在主手物品通过装备签名且类型为 `WEAPON` 时提前取消副手交换事件；`Q` 永远保持原版丢弃，普通原版物品的 F 也不受影响。职业与五维使用玩家熟悉的原版武器、盾牌、羽毛和书。原创 `item_model` 只有在完整资源包通过客户端验收后才可显式启用；拒绝或尚未加载资源包时使用原版图标，避免缺失模型变成黑紫方块。所有图形点击仍回到原命令和服务端事务校验，GUI 不是安全边界。

## 粒子和声音预算

技能采用职业可读的统一色彩：奶妈为薄荷绿、战士为赤红、刺客为暗紫、火法为橙焰、冰法为冰蓝、游侠为青蓝、散人为金色；反转治疗使用血红，明确区别于正常治疗。每次成功施法只发出一次中心粒子批次和一次声音，不启动永久追踪任务。

玩家外观以更低优先级运行：光环、鞘翅轨迹和低频庆祝共用一个每 5 tick 调度器以及全局发送预算，正常状态每次最多 240、压力状态 64、严重状态 0。单个发射者只向 24 格内最多 6 名接收者发送；接收者自己的 `/visuals` 还可继续降低或关闭。预算优先保证一次性庆祝和真实滑翔轨迹，地面光环最后使用剩余额度。攻击、受击后的 8 秒以及动态副本世界均不渲染常驻外观，滑翔时也不会叠加地面光环。

`RpgPerformance` 会把技能单次粒子量从正常 20 降到压力 8、严重 2；副本地面环则从 24 点降到 10 和 3 点，严重状态关闭次级粒子。Boss 现已在出场前 30 tick 发出地面轮廓和声音预警，出场、波次苏醒和击杀各只触发一次，没有永久高频任务。视觉降级不改变伤害、治疗、范围、冷却或掉落；即使不加载资源包，玩家也能通过原生粒子、声音和中英文提示读懂关键危险。

## 已采用的内容组件与后续候选

- Citizens2 已为序章巡路采用，但不替换固定柜台；后续只有隐藏副本侦察、血月撤离、隐藏职业试炼和少量章节走位能申请动态演员预算。
- BetonQuest 已为 `sivita_story` 中英文内容包采用，但不替换任务中心；新增脚本动作必须先在自研桥中成为可审计的窄接口。
- GrimAC 是公开测试候选；职业冲刺、击退、御剑/飞行和副本位移没有完成误报矩阵前不能开启自动处罚。
- 方块回滚仍缺少已验证的 26.2 稳定免费发行。CoreProtect 的兼容分支和公开二进制状态重新统一前，不下载旧版或来源不明 fork。
- 原版长期生存仍采用单床家园纵切：EssentialsX 已安装但其 home/back/spawn/warp/economy/kit/repair 等冲突命令关闭，不建立第二套位置或余额数据库。玩家在主世界床旁 `/sethome`，只在主世界使用 `/home`；预热 5 秒，移动/受伤取消，冷却 10 分钟，战斗与副本内失败关闭。床被破坏或堵住时同时失去原版重生点和家园；下界/末地仍使用原版传送结构，长距离传送继续触发连猎重置。

## 运行验收状态

Paper 26.2 运行基线现为 40 个插件（25 自研 + 15 社区）。主城位于独立虚空世界 `sivita_hub`，有 11 名低开销固定功能 NPC、1 名 Citizens 剧情演员、全域禁刷怪/伤害/建造和 48 边形 WorldGuard 保护。六类副本各保持 1 个热实例，总世界硬上限 16；主世界、下界和末地锁定在 1800/900/1200 半径的方形边界，边缘相交区块必须由维护脚本核验后才算完整预生成。GriefPrevention 仅接管原版主世界生存领地，SkinsRestorer 已启用 Paper join listener；EssentialsX 与 MyPet 分别被限制为基础工具层和宠物实体/AI 层；BetterModel 3.3.0 仅渲染经审核的完整稀有怪外壳；BetterHud 只投影内存快照并静态并入唯一资源包。LAN 官网监听 `0.0.0.0:8080`，squaremap 只监听 `127.0.0.1:8081` 并由官网 `/map/` 提供；生产仍由 Caddy 统一暴露 HTTPS，不公开后台端口。

尚不能由空服启动替代的真人验收包括：AuthMe 登录前无法移动/聊天/执行非白名单命令；LuckPerms context 与 38 个占位符随真实档案刷新；WorldEdit 限额生效；WorldGuard 具名区域不拦截锻造和菜单；Chunky 不处理副本世界；官网 `/map/` 反代和强制资源包在目标 HTTPS 域名工作。任何插件若无法满足这一边界，应移除，而不是绕过自研安全规则迁就它。

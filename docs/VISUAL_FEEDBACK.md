# 视觉反馈规范

视觉层只表达已经发生的结果，不参与命中、伤害、掉落、扣款或成功率计算。玩家可用 `/visuals` 在完整、精简、
极简和关闭之间切换；服务器进入 `PRESSURE` 或 `CRITICAL` 时会在玩家档位之上继续降级，但不改变任何数值规则。

## 交互通道选型

本方案在 2026-08-06 对照了 Paper/Adventure 的
[Dialog](https://docs.papermc.io/paper/dev/dialogs/)、
[Display Entity](https://docs.papermc.io/paper/dev/display-entities/)、
[Title](https://docs.papermc.io/adventure/titles/)、
[Player List](https://docs.papermc.io/adventure/tablist/)、
[Sound](https://docs.papermc.io/adventure/sound/) 与
[Resource Pack](https://docs.papermc.io/adventure/resource-pack/) 能力。每种通道只承担一种信息层级，避免多个常驻 UI
相互抢占。

| 通道 | 本服用途 | 更新约束 | 结论 |
|---|---|---|---|
| 原版物品模型、附魔光泽、完整怪物骨骼外壳 | 装备方向、品质、稀有材料和稀有怪身份 | 物品由客户端渲染；怪模只在视线内 48 格追踪 | 主视觉；禁止只换头、头盔面具或原实体与模型重叠 |
| 自定义图标 | 49 张按最终 18×18 分辨率绘制的职业/技能图标、八步旅程图标及法力、事件、地点等基础像素图形 | BetterHud 通过 `<image:...>` 编译进自己的定位字体；不再直接注入 PUA 字体。仅在客户端加载生产资源包后启用，否则回退原版物品和文字 | 可选 HUD 增强；避免黑紫方块和定位黑框 |
| 26.2 Dialog / Quick Actions | `G` 键总入口、当前八步目标、八步完成后的实时路线建议、16 主题情境帮助、NPC 对话和 AI 输入 | 玩家主动打开；G 走版本化数据包，个性化页面走 Paper API；所有按钮回到现有服务端命令/事务 | 低频解释与导航入口，已启用 |
| Inventory GUI | 主菜单、帮助、技能树、市场、锻造和强化 | 玩家主动打开才创建；点击服务端校验 | 复杂选择的主通道 |
| BetterHud 战斗轨 | 屏幕右侧中部纵向四槽技能图标、选中框、逐秒 CD、竖向法力条；职业徽记/等级贴在技能轨左侧 | 10 Hz 客户端布局、1 Hz PAPI 内存快照；四槽始终保留真实位置，空槽不会把后续技能挤位；默认示例 HUD/实体条/罗盘全部关闭 | 释放物品栏上方和中心 ActionBar，不占生命、饥饿、经验、物品栏、聊天或计分板 |
| ActionBar | 当前目标生命、施放结果、连猎与即时限制 | 只发相关玩家；不再常驻重复四技能 HUD | 高频短状态的主通道 |
| Title/Subtitle | 血月、稀有锻造、技能异变、首领阶段 | 只用于低频里程碑 | 稀有事件强调 |
| BossBar | 玩家主动开启的主城导航、副本首领、血月等全局事件 | 导航停止即清理；Boss 受伤同 tick 合并；血月每 5 秒更新 | 临时方向或长进度，不承担常驻帮助 |
| Tab Header/Footer | 仅职业、转生、等级和最多 2 个已学技能/CD；正在冷却的技能优先，按最早就绪排序 | 每 100 tick 检查；签名不变不发；只读缓存 | 玩家主动按住 TAB 的角色战斗摘要；不重复目标、体力、经验、TPS 或命令提示 |
| NPC TextDisplay | 仅一行 NPC 身份牌 | 单个 NPC 固定一个标签；24 Unicode 字符上限；18 格外不跟踪 | 世界辨认，不显示职责、任务或玩家状态 |
| 定向音效 | 技能、稀有掉落、锻造结果与大事件 | 一次事件最多一个主音效；遵从 `/visuals` | 不依赖视线的辅助反馈 |
| 定向粒子 | 技能轮廓、命中点、首领预警和稀有结果 | 仅相关玩家、8–64 格、受负载与偏好双重降级 | 空间反馈，不承担文字信息 |
| 药水图标、原版投射物、原创弹体 | Buff/Debuff、可被地形阻挡的箭、腐蚀弹/回旋刃/巡弋星弹 | 原版实体沿用同步生命周期；原创弹体由有界序列和资源包模型管理 | 与原版机制融合，但不把全部技能降格为药水与箭 |

以下能力不是“不会做”，而是当前不适合核心热路径：

- Paper Dialog API 仍标记为实验性，因此只承担可替换的低频解释、输入与导航。副本命中、市场结算、锻造、强化和奖励均不依赖 Dialog；数据包或 API 页面失效时仍有旅者罗盘、`/menu`、命令和 NPC 入口。版本升级必须先验证 Dialog API、`#minecraft:quick_actions` 和 pack format，再更换生产数据包。
- Text/Item/Block Display 仍是需要追踪和清理的实体；不用于伤害数字、技能轨迹或常驻全息。以后若做固定大厅展示，必须有
  固定数量、区块卸载和插件关闭清理测试。
- Advancement Toast 适合固定成就，不适合动态伤害、掉落和冷却；动态注册还会增加数据包/注册表维护面。
- 不创建计分板侧栏。新手目标由旅者罗盘、G 快捷操作、情境 Dialog 和玩家主动开启的路径导航表达，避免与右侧战斗轨、聊天或其它插件的队伍/前后缀争抢屏幕。
- 经验条保留原版经验语义，不伪装成法力；物品冷却遮罩只有未来技能真正绑定专用快捷栏物品时才可使用，不能覆盖普通物品。
- 地图画布、客户端 Shader、资源包字体负间距技巧和世界边界染色不用于关键规则，避免版本脆弱、视觉障碍或客户端兼容问题。

## 信息层级

| 场景 | 主反馈 | 辅助反馈 | 明确不使用 |
|---|---|---|---|
| 普通攻击 | 原版受击 | 攻击者 ActionBar 生命条 | 额外攻击音、伤害数字实体 |
| 暴击/处决 | 定向 CRIT/FLASH、攻击者音效 | ActionBar 标签和目标生命 | 世界广播、持续全息 |
| 职业技能 | 职业色形状、单个主音效 | 5 秒法力/冷却 HUD | 每 tick 声音、无限 Display |
| 精英/稀有掉落 | 出生一次短提示、击杀者掉落提示 | 经审核的完整身体模型/原创物品模型 | 单独头模、普通怪持续粒子 |
| 副本 | 波次传送环、BossBar | Boss 出现/击败一次反馈 | 跨世界发送 |
| 血月 | 每玩家 BossBar、开始 Title | 每 5 秒 1–3 个环境粒子 | 每只普通血月怪播放声音 |
| 连猎 | 常驻 ActionBar 文本 | 10/25/50/100 层里程碑效果 | 每次击杀叠音效 |
| 锻造/强化 | 结果粒子、一次音效 | 稀有锻造/技能异变 Title | 结算完成前预播成功效果 |
| 硫灵调谐/剪取 | 仅交互者可见的黄/朱砂红渐变与一次共鸣音 | ActionBar 倾向、聊天额度 | 世界广播、常驻实体、每 tick 追踪 |

## 职业辨识

- 奶妈使用青绿色光环；治疗反转为玫红色前向伤害。
- 战士使用红橙色扩散波，强调范围与防线。
- 刺客使用紫色烟幕环，强调位移和隐匿。
- 法师按火、冰、奥术分别使用橙、冰蓝、紫色轨迹。
- 游侠使用青蓝前向轨迹，保留原版箭矢飞行反馈。
- 散人使用金色奥术螺旋，表示组合与随机性。

## 包预算与清理

- 粒子默认只发给施法者、攻击者、掉落归属者或 40–64 格内相关玩家。
- 普通攻击不添加音效；一次技能、Boss 事件或强化结果最多一个主要音效。
- `FULL/REDUCED/MINIMAL/OFF` 的粒子倍率为 `100%/45%/0%/0%`，声音倍率为
  `100%/70%/35%/0%`。
- 高压状态通常减半粒子，严重状态保留 0–3 个关键粒子；BossBar、ActionBar 和规则提示始终保留。
- 职业技能正常档单次对单个接收者最多约 12 个粒子发送调用；严重档只保留一个最多 2 粒子的调用。命中点不使用世界广播。
- BetterHud 使用按槽位拆分的只读占位符与 49 个动态 `<image:...>` 图标，所有值来自同一份每 20 tick 刷新的内存快照，不为每项技能建立独立任务，也不读取 JDBC；插件整体 `tick-speed=2`。四槽改为右侧中部 26×91 逻辑像素纵轨，职业徽记放在轨道左侧；资源包加载成功后不再发送旧 ActionBar 技能条，中心只显示短时施放/切换反馈。旧条仅作为拒绝或加载失败时的降级界面。轨道的尺寸契约（26×91 轨 / 49 张 18×18 图标 / 29×26 徽章 / 1×87 法力 / 4 槽 22px 影格）只有一份真相源 `docs/reference/hud-layout.json`，被资源包门禁、`build.sh`、插件侧 `HudRailSpec` 三边读取，单边改动会被拦下；对齐过程与三处「基准值做不到」的实测结论见 `docs/hud-imagegen-prompt-v2.md` 的 implementation note。Tab 最快每玩家每 100 tick
  一包且同样做内容差分；候选超过两项时优先投影仍在 CD 的技能，避免真正需要查看的状态被配置顺序遮住。
- `/guidehud on|off` 只控制 BetterHud 右侧战斗轨，并把偏好保存在玩家 PDC；HUD 会话重建后自动恢复。引导目标不随该开关消失，旅者罗盘、G、Dialog、导航与 TAB 回退始终可用。
- 未选择职业时 `/skills` 只显示“先选择职业”的单入口页，不渲染 42 个跨职业锁定技能。技能页只承担学习、连续升级、查看和四槽装配，不允许菜单点击施法；手持已签名自制武器时，纯服务端监听把单按 `F` 变为施放、双按 `F` 变为切换，并在副手交换前取消事件。`Q` 始终保持原版丢弃；普通原版物品的 F 与 `1–9`、滚轮、`Shift` 均保持原版行为。首次欢迎 Dialog 和八步旅程明确说明上述操作；技能缓存未就绪时显示“载入中”，不伪装成 `0/0`。
- Tab、技能 HUD、Placeholder 和状态页只读取内存快照，渲染路径严禁发起 JDBC、网络或文件读取。
- 血月 BossBar、技能 HUD、玩家缓存和副本 BossBar 必须在退出、切世界和插件关闭时清理。技能冷却/法力离线缓存保留 120 秒再清理，防止重连重置冷却，同时保证内存有界。
- 不为伤害数字创建 TextDisplay，不让临时实体随战斗次数增长。
- 副本的逐 tick 任务只处理脏 BossBar 或正在分片写入的竞技场；空闲时不扫描世界池，等待队列超时每秒检查一次。
- 普通怪身体始终使用完整原版渲染；少量特性怪只在施法窗口显示有界线、圈、声音和原创弹体。完整自定义身体模型只分配给有辨识价值的精英、血月稀有怪和 Boss。`RpgMobs` 的全服模型上限为正常 64、压力 20、严重 0；协调每 100 tick 一次，BetterModel 另启用视线裁剪、48 格视距和 24 包合并。
- BetterHud 全局字体与战斗字体只生成拉丁、数字和图标页；中文说明交给原生菜单、Dialog 与聊天字体。发布脚本拒绝超过 48 个 HUD 字体页的构建，当前合并包约 230 KiB。
- 模型外壳不拥有碰撞、寻路、目标、伤害、处决判断或掉落。资源包失败、模型解析失败或严重负载时必须恢复完整原版实体，不能留下隐形怪、不可点击怪、双重身体或只剩一个方块头。

## 验收

至少用两名玩家分别设置 `full` 与 `off` 测试同一场战斗，确认数值和掉落完全一致；再使用性能管理命令切换压力状态，
确认只减少视觉包。学习三个技能并让第三个进入 CD，按 TAB 必须看到该冷却技能被提升到前两项；GUI 缩放 2/3/4 下右侧纵轨不得越界，也不得覆盖中心 ActionBar、聊天和原版生存 HUD；拒绝资源包后，旅者罗盘、Dialog 与
TAB 必须仍以普通中文/英文清楚显示且没有私用区方块。血月、停止主城导航、退出副本、切世界和插件停服后不应残留
BossBar。锻造/强化失败、保护生效和扣款退款必须与显示结果一致。

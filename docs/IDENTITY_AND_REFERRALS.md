# 玩家身份、防小号与推广归因

## 已实施的身份边界

身份链只有一个根：离线 UUID 对应的游戏角色。AuthMe 负责游戏内密码和登录冻结，官网不复制密码库，也不开放另一套邮箱/密码注册。

当前 26.2 客户端在配置阶段先看到原生 Dialog，未完成认证前不会进入世界、加载玩法 HUD 或看到主城 NPC；取消会直接回到服务器列表，不再进入世界后叠加第二个窗口。窗口以中文为默认，并保留简短英文说明；进入游戏后 AuthMe 会按客户端语言选择完整中文或英文消息。命令仍是无 Dialog 时的兜底，不是首选入口。

游戏密码边界为 10–64 个可见 ASCII 字符，使用 BCrypt cost 12 异步校验，常见密码、角色名和服务器名组合被拒绝。认证命令由 AuthMe 的日志过滤器遮蔽；自动 IP 会话保持关闭，避免家庭、宿舍或网吧共用公网 IP 时被同名冒用。单角色只允许一个已认证连接，普通玩家也不会在登录时看到同网络的其他账号名。

玩家认证后输入 `/account link`，服务端生成 5 分钟有效的 HMAC-SHA256 签名令牌。令牌包含 UUID、当前游戏名、邀请码和一份成长快照，使用 144 位随机 nonce，只能消费一次。令牌放在 URL fragment 中，浏览器脚本读取后立即清除；fragment 不会随 HTTP 请求进入访问日志。

官网消费令牌后建立 HttpOnly、SameSite=Strict、IP/浏览器指纹绑定的玩家会话。换设备时回到游戏重新签发，不设置可撞库的第二密码。

## 防小号不是“一刀切 IP 封禁”

目前采用分层约束：

1. AuthMe 每 IP 最多注册 2 个账号，并强制单会话，密码哈希和数据库操作保持异步。
2. 新手八步不再产生可转移金币，只奖励账号绑定功勋；初始金币为 0。
3. 师徒邀请码只能在有效等级 10 以内、真实游玩 360 分钟以内绑定，不能自己邀请自己。
4. 有效招募必须完成八步旅程、达到有效等级 15、累计真实游玩 180 分钟。
5. 邀请结果只增加不可交易社群成就与榜单，不直接发金币、装备或材料。
6. 官网只保存 HMAC 隐私哈希后的网络/浏览器信号。30 天内同网络出现多个 UUID 时标记 `REVIEW`，不自动封禁，以免误伤家庭、宿舍或网吧。

`REVIEW` 玩家可在官网档案提交幂等的人工复核申请。申请不接受自由文本，也不收集身份证、手机号、地址或原始 IP；唯一 OWNER 在独立后台“玩家复核”队列批准或驳回，结论和申诉编号进入管理员审计。批准只解除推广复核信号，不改变角色、经济或游戏处罚；再次出现新的同网络信号时仍可重新进入复核。

这套规则让一次性小号没有可搬运的启动物资；长期养成一个小号的成本又接近正常玩家。VPN、设备指纹和 IP 都不能单独证明“同一人”，因此只进入审计，不作为自动处罚证据。

## 推广流程

老玩家在官网档案复制自己的推广说明页。新人进入服务器后，在绑定窗口内执行 `/community bond <邀请码>`；官网绑定用于统一展示和后续活动领取，游戏数据库里的师徒契约仍是权威归因。

有效状态到达前不预发奖励。未来活动若增加奖励，只能从以下类别选择：

- 官网徽章、称号展示、社群装饰进度；
- 账号绑定且不可交易的外观凭证；
- 不增加装备上限、掉落率或交易财富的便利收藏。

禁止给推广者或新人发可交易金币、白板装备、锻造材料、保护石或幸运符。否则即使设置等级门槛，也会形成批量养号套利价格。

## 数据与部署

本机局域网使用网站内存存储测试玩家会话，重启网站后需要重新绑定；正式服使用 PostgreSQL 的 `sivita_web_player_*` 表。游戏服首次启动会在 `server/runtime/secrets/account-link.key` 创建 256 位密钥，权限为 owner 读写、同组网站服务只读。分离部署时通过只读 secret mount 向两端提供同一密钥，密钥不写入仓库或网页配置。

管理员后台与玩家会话使用不同 Cookie、不同表和不同认证函数。官网公开导航只显示“玩家档案”，不会暴露管理员后台入口。

## 公网迁移前的认证门槛

AuthMe 6.0 的配置阶段 Dialog 能避免玩家在认证前进入世界，但该版本的 pre-join 密码比较没有复用 post-join 的 `TempbanManager` 失败计数。当前局域网基线仍有 Bukkit 4 秒连接节流、AuthMe AntiBot、强密码和每 IP 并发限制；迁移到公网入口前还必须在 Velocity/反向入口按源地址和角色名增加滑动窗口失败限速，或升级到已把 pre-join 失败接入临时封禁的 AuthMe 版本。这个门槛不能用扩大 IP 注册封禁替代，也不能声称现有验证码已经覆盖配置阶段。

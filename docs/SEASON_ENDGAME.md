# 赛季终局纵切：每周共鸣远征

本页描述已经进入代码和数据库的第一条可重复赛季终局，不把未来策划当成现状。它同时覆盖周轮换词缀、图鉴章、个人最佳、分队规模竞速榜和全服首通，但不宣称单条纵切已经构成多年内容量。

## 玩家循环

玩家使用 `/dungeon season` 查看当周目标、两个真实词缀、周重置时间、赛季荣誉、图鉴章、本人当前队伍规模最佳和全服首通。`/dungeon season enter` 按当前副本队伍进入当周挑战；`/dungeon season top 1|2|3|4` 查看对应人数榜。

共鸣远征复用普通副本的体力、等级、队伍、实例池和普通掉落，不另造一套入场资源。只有从专用入口进入的会话才应用词缀和计时，普通 `/dungeon enter` 不会被动变难。

有效完成必须满足：

- 开始时的 1–4 名队员全部留在实例中并共同完成；离线、主动离开或死亡退出会保留普通副本结算，但取消赛季记录。
- 计时从全员成功传送后、第一波生成前开始，到受管理的首领死亡为止；排队和实例构建时间不计入。
- 挑战必须在同一轮换窗口内开始并完成。跨过周一 00:00 不追认旧周，也不会把旧词缀成绩写进新周。
- 竞速按 1、2、3、4 人分榜；同一成员组合只保留最快一条榜单记录，不能用重复慢成绩占满前十。

## 轮换与真实词缀

权威时区为 `Asia/Shanghai`，每周一 00:00 切换。轮换 ID 使用周一日期，例如 `week-2026-08-03`。远古遗迹、硫泉深窟和风暴秘库逐周轮换；六组词缀配对与三族目标组成完整 18 周组合周期，然后才重复。

| 词缀 | 服务端效果 |
|---|---|
| 森严 | 首领生命 +25%，波次守卫生命 +15% |
| 不息 | 首领地面机制间隔缩短 18%，仍受 60 tick 安全下限保护 |
| 群涌 | 每波守卫数量 +30% 并向上取整，仍受单波 24 只硬上限保护 |
| 凶烈 | 守卫、首领普攻与地面机制伤害 +15%，仍受原有伤害硬上限保护 |

这些变化只在实体生成或既有首领机制调度时计算；没有新增逐 tick 全世界扫描、全量粒子或额外寻路器。

## 奖励与经济边界

每名玩家每个轮换第一次有效完成获得 100 赛季荣誉和一个图鉴章；该周全服首通成员再各获得 50 荣誉。数值由 `RpgCore` 配置限制在单项 0–1000，当前分别为 100/50。

赛季荣誉是隔离的展示分：

- 没有兑换为金币、功勋、星辉、物品、掉率或战力的 API 与商店路径。
- 重复通关只增加有效完成数并刷新个人/队伍记录，额外金币净流入恒为 0。
- 共鸣远征仅保留副本本来就会产生的体力消耗和普通掉落，不叠加可交易周奖励。
- 新玩家可以争取后续周的图鉴章与榜单，不需要通过追发金币补齐旧周。

因此运营不能把赛季荣誉接入财富兑换；若未来增加外观里程碑，必须只发不可交易、无战力的账号收藏，并另做原子领取表。

## 事务、幂等与首通竞争

`SeasonExpeditionService.complete` 使用每个实例唯一且重试时不变的 `runId`。一次事务内完成：

1. 锁定 `season_id + rotation_id` 的轮换行并确认目标副本一致。
2. 插入唯一运行记录与成员记录。
3. 竞争并写入唯一全服首通。
4. 以 `season + rotation + player` 唯一键领取周荣誉/图鉴章。
5. 更新赛季累计档案和按队伍规模划分的个人最佳。

相同 `runId` 重试返回 `DUPLICATE` 且不再加分；换 `runId` 重复刷同周也只能刷新纪录。Paper 端数据库失败使用同一 `runId` 最多重试三次。20 路并发合同测试证明同一玩家同周只有一次领取、全服只有一个首通。

相关六张表为：

- `rpg_season_rotation_state`
- `rpg_season_runs`
- `rpg_season_run_members`
- `rpg_season_player_progress`
- `rpg_season_rotation_claims`
- `rpg_season_personal_bests`

H2 → PostgreSQL 工具已把这些表纳入完整清单、主键和摘要校验，不能静默漏迁。

## 重置和归档

周重置不会删除任何行；新的 `rotation_id` 自然形成新领取额度、新首通和新榜。赛季档案按 `season_id` 隔离：进入新赛季后新荣誉和图鉴从 0 开始，旧赛季仍可查询，不能直接清表。

这不等于已经完成正式换季事务。现有功勋钱包、Raid 凭证、高阶核心和旧装备仍缺少带预览、审计、回滚的跨赛季结算；在该事务完成前只能在 `launch-1` 内使用本纵切，不能只修改 `chapters.season-id` 宣称完成换季。

换季事务已具备的部件（能力接线，默认关）：赛季层功勋结清（`season.settlement.enabled`）与
旧装备的第五层退出路径「赛季调谐」（`season-attunement.enabled`）。调谐由结算在 SETTLING
阶段触发，装备身份收口成 `SEASON_ATTUNED` 后经唯一市场邮箱交还原持有者；它不发布玩家指令，
也不结算任何货币。在 20 人以上真实运营 [R]/[H] 门禁通过前，两项开关保持关闭。

## 仍未完成的长期内容

本纵切解决“有无可重复赛季记录层”，没有解决“多年内容量”本身。继续开放万人服前仍需：

- 至少再做两种不依赖现有六副本的终局循环，例如区域入侵共同目标和原版袭击变体。
- 为 18 周组合做真人难度/通关时长分布校准；当前倍率是受硬上限保护的首发基线。
- 增加只读赛季档案与往季荣誉展示，但不能把管理员后台入口暴露在公开页。
- 为图鉴章制作无战力收藏里程碑和原子领取，而不是增加可交易材料。
- 做正式新赛季的功勋、凭证、核心与旧装备结算事务。
- 完成真实 PostgreSQL 并发/故障恢复、50/70/100 人阶梯压力和至少一个完整 18 周周期的数据验收。

首通广播和按队伍规模榜能形成可截图、可组队追赶的自然传播点，但它们不是拉人返利。推广/师徒奖励仍必须以真实活跃验证、账号/设备风控和绑定非战力奖励为边界，不能通过小号给邀请者铸币。

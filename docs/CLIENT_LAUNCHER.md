# 希维塔大陆客户端与启动器方案

更新时间：2026-08-11。本文记录“任意兼容客户端直接加入”的当前方案；不开发、不发布也不要求希维塔专用客户端。

## 结论

服务器以原版 Minecraft Java 26.2 客户端为兼容基线，不要求 Fabric、Forge、NeoForge 或任何 SivitaHub 客户端扩展。原创模型与 HUD 由连接时自动下载的服务器资源包提供；技能输入、伤害、掉落、经济和角色数据全部由服务端处理。玩家可以用任意能正常启动 Java 26.2 的启动器直接连接。

暂不 fork 或包装“希维塔专用启动器”。自有启动器会立即带来 Windows/macOS 代码签名、自动更新、账号令牌保管、三平台安装器、供应链审计和长期兼容责任；这些成本目前不会给服务端玩法增加价值。

## 为什么不要求整合包

- 职业、装备、野怪、副本、交易和经济仍全部由服务端权威结算，客户端不能修改结果。
- 原创物品、怪物和 HUD 仍由 `require-resource-pack=true` 统一下发，不在实例里维护第二份资源包。
- 手持自制 RPG 武器时，服务端把单按 `F` 解释为施放当前技能、双按 `F` 解释为切换已装配技能，并在副手交换发生前取消事件；不需要客户端把自定义按键传给服务端。
- `Q` 始终保持原版丢弃；手持普通原版物品时 `F` 也保持原版行为。`1–9`、滚轮和 `Shift` 不被技能系统占用。命令 `/skills castslot 1–4` 仅保留为测试与无障碍兜底。
- 当前不混入尚未完成 26.2 多平台回归的性能、光影或玩法模组，保持依赖面最小。

## 玩家首选：XMCL

XMCL 官方说明支持 Windows、macOS、Linux，可下载 Minecraft、Fabric/Forge 与 JVM，并支持 Microsoft、离线及第三方认证配置。当前服务器关闭正版验证并由 AuthMe 在服内认证，因此玩家可建立与游戏名一致的离线档案。

推荐操作：

1. 只从 [XMCL 官网](https://xmcl.app/) 或其官网指向的 GitHub Release 下载。
2. 新建纯 Minecraft Java `26.2` 实例；不必选择任何模组加载器，也不必安装额外 JAR。
3. 允许启动器自动下载匹配 JVM；不要手工把系统 Java 8/17 指给 26.2。
4. 建立离线账号，游戏名使用 3–16 位字母、数字或下划线。这个名字决定离线 UUID，后续不要随意改名。
5. 添加服务器 `mc.sivitahub.com`；默认端口为 `25565`，无需填写端口或 SRV。
6. 连接时会先出现“希维塔大陆 · 创建旅者”原生窗口。创建一个 10–64 位、只用于本服且不与其他网站共用的密码；以后连接使用“旅者登录”窗口。命令 `/register 密码 确认密码` 和 `/login 密码` 仅作窗口不可用时的兜底。
7. 完成认证并进入主城后，可用 `/account link` 生成一次性官网绑定链接；官网不会读取或保存游戏密码。

官方依据：[XMCL 功能与 JVM 下载](https://xmcl.app/en/about)、[XMCL 账号支持](https://xmcl.app/en)、[离线认证接口](https://xmcl.app/en/core/user)。

## 其他启动器

Prism、HMCL 或其他能够启动纯 Minecraft Java 26.2 的启动器都可以使用。只需自行建立纯原版实例并添加 `mc.sivitahub.com`；不要导入希维塔 ZIP，也不需要安装整合包。启动器自身是否允许离线身份、怎样下载 Java，属于该启动器的能力边界，不改变服务器兼容性。

## 性能模组边界

当前不建立服务器专用性能包。玩家自行使用纯客户端性能模组时，服务器仍只保证纯原版 26.2 客户端路径；遇到显示、输入或资源包问题时，先用新的纯原版实例复现。

## 三平台常见问题

### Windows

- 不需要另外安装 Oracle Java；让 XMCL/Prism 管理 JVM。
- 防火墙只需允许启动器和 Java 访问网络，不要关闭系统防火墙。
- 黑紫方块表示资源包未加载：在服务器编辑页把“服务器资源包”设为“启用”，删除该服务器旧的失败缓存后重连。

### macOS

- Apple Silicon 使用 arm64 启动器包；Intel Mac 使用 x64 包。
- 只从官方已签名/公证的发行页下载。若 Gatekeeper 报警，先核对来源与校验值，不使用来源不明的“一键破解器”。
- 让启动器选择对应架构 JVM，避免用 Rosetta 混跑 Java。

### Linux

- 优先使用官网列出的 AppImage、Flatpak 或发行版包。
- Flatpak 若不能访问自定义实例目录，应通过其权限管理界面授权，而不是以 root 运行启动器。
- Wayland/X11 的显卡问题先用纯原版实例复现，再单独排查玩家自行安装的性能模组。

## 资源包与身份故障排查

1. 服务器列表能进、菜单全是黑紫方块：客户端未成功下载资源包。先确认 `https://mc.sivitahub.com/resourcepacks/sivita-hub-26.2.zip` 可下载，再把客户端的“服务器资源包”设为“启用”。
2. 下载成功仍显示旧图：完全退出客户端再启动；服务器会用新的 `resource-pack-id` 使失败缓存失效。
3. 注册提示同 IP 数量已满：AuthMe 当前限制每个真实公网/LAN 来源 IP 2 个账号；FRP 与 Paper 之间用受信任的 PROXY v2 链路保留来源地址。家庭共用网络确有需要时由管理员人工核验，不临时关闭全服限制。
4. 换电脑登录官网玩家档案：进服认证后重新输入 `/account link`；不要复制浏览器 Cookie，也不要把一次性链接发给别人。
5. 认证窗口显示中文但客户端使用英文：配置阶段尚未创建 Player，AuthMe 无法读取客户端语言，因此首屏采用简短中英双语；进入游戏后的认证消息会按客户端语言切换。

## 交付边界

官网只提供服务器地址、版本、资源包故障排查和通用启动说明，不提供客户端 ZIP、自动登录配置或私有模组包。任何说明都不包含 AuthMe 密码、离线玩家名预设、管理员地址、API 密钥或服务器私有源码。

# Minecraft 26.2 原版融合审计

审计日期为 2026-08-06，运行基线为 Paper `26.2.build.100-stable`、Java 25。实现同时对照了
[26.2 社区条目](https://minecraft.wiki/w/Java_Edition_26.2)、
[Paper 26.2 Javadoc](https://jd.papermc.io/paper/26.2/)、
[Data Component API](https://docs.papermc.io/paper/dev/data-component-api/) 和本机构建所用 Paper API JAR；
没有仅凭视频或旧版插件文档猜测类名。

## 最终融合方案

26.2 的硫磺洞穴、硫磺、朱砂和硫磺方块生物进入既有装备循环，不建立第四套货币或孤立掉落表：

```text
原版洞穴探索
  -> 纸 + 硫磺 + 朱砂合成空白锻纹
  -> 向硫磺方块生物喂入一个物理原型方块
  -> 剪刀 + 另一只手的空白锻纹进行剪取
  -> 账号绑定、签名的硫灵锻纹
  -> 锻造第四槽
  -> 装备使用揭示槽位
  -> 成功精炼时按锻纹改变属性抽取权重
```

`rpg-sulfur` 直接监听 `SulfurCubeSwallowItemEvent`，不轮询实体，也不替换生物 AI。普通原型强度为 2，
目标属性权重从 100 提高到 250，因此八属性池中的实际概率从 12.5% 变为 `250/950 = 26.3%`；
强原型为 3，对应 `325/1025 = 31.7%`。锻纹不改变锻造或精炼成功率，不锁槽、不保证正数值，避免把新版探索变成
低成本必毕业路径。

| 喂入原型 | 精炼倾向 | 设计含义 |
|---|---|---|
| 原木、木材、菌柄、木板 | 敏捷 | 轻量、弹性与攻速构筑 |
| 石材、深板岩、矿石、黑曜石、凝灰岩 | 防御 | 密度和承载 |
| 铁、铜、金、下界合金块 | 力量 | 重量和冲击 |
| 羊毛 | 智力 | 柔性媒介与法术编织 |
| 蜂蜜/蜜脾方块 | 治疗效率 | 修复与黏合 |
| 冰、硫磺 | 技能急速 | 滑动或快速反应 |
| 朱砂 | 暴击 | 高风险精确触发 |
| 强效硫磺、岩浆/熔岩原型 | 三级强共鸣 | 稀有原型；仍不保证结果 |

成品锻纹有独立 HMAC、唯一 ID、所有者、原型、倾向和强度。锻造时这些字段再写入装备 schema 4 的 canonical
签名，因此修改 PDC、复制部分字段或伪造解绑都会使装备失效。市场和容器边界识别 `rpgsulfur:owner`；空白锻纹可流通，
成品只能由调谐者使用。每日剪取上限 6，同一生物成功剪取后冷却 300 秒，喂入方块、空白锻纹和锻造失败共同形成材料回收。

## 没有强行使用的 26.2 API

- `SulfurCubeContent` Data Component 适合物品形态的硫磺方块生物内容；当前实时实体流程已有专用吞入事件，核心状态不依赖
  实验性组件。以后若把装有方块的生物装桶交易，必须同时验签桶内容，不能只信客户端组件。
- `AIR_DRAG_MODIFIER`、`FRICTION_MODIFIER` 和 `BOUNCINESS` 不直接永久施加到玩家。它们容易影响跑酷、领地边界、
  反作弊和原版移动预期；可在隔离副本中作为短时地形词缀试验，但不能进入通用装备随机池。
- `AttackRange`、`Weapon`、`KineticWeapon`、`PiercingWeapon`、`SwingAnimation`、`UseCooldown` 和 `UseEffects`
  可增强客户端表现，却不能代替服务端伤害、冷却和签名事实源。首发继续由统一战斗管线结算，避免客户端表现组件成为作弊入口。
- Paper Dialog 仍用于低频教程候选，不让交易、锻造和副本依赖实验界面；Inventory GUI 保留稳定的服务端点击复核。

## 原版床就是唯一家园

家园没有引入 EssentialsX，也没有维护第二份坐标。`/sethome` 只接受玩家附近的主世界床，并通过 Paper 26.2 的
`Player#setRespawnLocation` 写入原版重生点；`/home` 再读取同一位置。床被破坏、移动或周围堵塞时不会使用旧坐标兜底，
因此原版重生风险和 RPG 便捷传送始终一致。

`RpgCombat` 以 12 秒共享战斗标签约束 `/hub`、`/wild`、`/home` 和 `/back`，标签在断线与重启边界保存；副本世界全部拒绝这些
逃生命令。家园另有 5 秒预热、移动/受伤取消和持久 10 分钟冷却。只允许从主世界发起 `/home`，避免把下界与末地的
原版传送结构变成摆设；目标区块异步加载，回主线程复核床、战斗状态、世界边界及两格安全空间后才传送。

## 性能与并发边界

- 吞入和剪取都是原版事件驱动，没有常驻扫描任务。
- 粒子只通过 `Player#spawnParticle` 发给交互者，最多 30 个，并同时服从玩家视觉档位和服务器负载降级。
- 每次成功剪取只做一次玩家 PDC 持久化；每日最多六次，不能形成主线程高频 I/O。
- 锻造扣款仍先异步提交账本，再回主线程重新核对四个输入槽；结算期间换物、关菜单或掉线不会白拿锻纹。
- 精炼只读取已被装备 HMAC 覆盖的倾向字段，权重选择为固定八项整数抽样，没有数据库或文件访问。

## 真人验收矩阵

自动测试覆盖材料映射、精确权重和输入边界；开放前仍需用 26.2 客户端完成下列行为测试：

1. 硫磺方块生物先后吞入受支持/不支持方块，确认旧调谐不会残留。
2. 主副手互换剪刀与空白锻纹，确认两种手位都只消费一个空白锻纹。
3. 他人剪取、日上限、冷却、重启后实体 PDC、死亡保留和容器/漏斗/丢弃限制。
4. 锻造扣款时关菜单、移动锻纹、掉线和数据库失败，确认金币退款且输入不复制。
5. 锻纹装备经精炼、绑定、解绑、市场、原版附魔/铁砧/饰纹/下界合金升级后仍能通过 schema 4 验签。
6. 中文、英文、完整和关闭视觉模式各走一次，确认只有表现不同，数值与消耗完全一致。
7. 床旁设置、床破坏/堵塞、移动/受伤取消、冷却跨重登、战斗/副本拒绝、下界/末地拒绝和安全落点逐项验证。

无法用静态代码证明任意第三方插件组合和任意人数下绝对零缺陷；以上矩阵、启动日志、阶梯压测和真实客户端回归是发布门槛。

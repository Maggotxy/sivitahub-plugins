# 玩法与经济宪法（最高机制约束）

> 版本：v1.0 | 生效分支：`planning/long-term-game-economy-v1`
> 任何玩法、数值、商店、赛季、货币改动若违反本宪法，不得直接实现，必须先提交 RFC 并修订宪法。

## 总则

本项目定位：**原版生存 × MMORPG 构筑 × 玩家经济 × 文明社区 × 软赛季历史**。
经济服务于完整循环，而非独立金币玩法。

---

### C-001 单一权威状态

任何系统（等级、货币、装备、市场、赛季、社群）只能有一个权威状态源。禁止双写、内存镜像、私有 YAML 覆盖数据库。

### C-002 货币只能通过账本变化

`gold / merit / starlight / support_credit` 的一切增减必须经过 `rpg-core` 账本事务：`余额表 + idempotency_key + 审计流水` 同事务提交。禁止直接 `UPDATE` 余额、内存补偿、命令刷钱。

### C-003 玩家交易不得铸币

玩家间交易（市场、委托对敲）只重新分配已存在金币，不得产生新金币。手续费永久销毁。

### C-004 可再生材料不能单独无限换钱

原木、作物、石材、铁等可再生/可自动化产出物，不得以固定价格 NPC 无限回购。必须经：托管市场（税销毁）或带「劳作证明+日限+账号时长」的委托回收。

### C-005 每个 Faucet 必须有四件套

任何铸币来源（狩猎/副本/委托/活动/兑换/补偿）必须同时具备：
`幂等键 + 日/周额度 + 指标 + Kill Switch`。缺一则视为未完成。

### C-006 退款必须引用原扣款

退款/冲正必须在同一事务内引用一条同玩家、同金额、尚未冲正的真实扣款流水，并受唯一约束。禁止凭空发钱补偿。

### C-007 货币兑换图无正价值闭环

兑换有向图以 `gold=1, merit=600, starlight=1400` 为参考价值向量检验，任一边使总价值增加则启动失败。每步净损耗 ⇒ 任意闭环净损耗。

### C-008 持续生成的高价值物品必须有退出路径

每种可重复产出的高价值物品（装备、稀有材料、门票）必须有至少一条销毁/退出路径：分解 / 献祭 / 传承 / 调谐 / 税收销毁。只进不出视为设计缺陷。

### C-009 市场只能有一套托管结算

自制装备、高价值材料只能通过单一托管市场流通（`PREPARED → ACTIVE → SOLD/CANCELLED/EXPIRED`，唯一 `item_id` 索引，税 5%/10%）。禁止第二套交易、面对面高价值直连、箱子商店复刻。

### C-010 换季必须事务化

赛季结算必须经 `SeasonSettlementService` 状态机：
`DRAFT → PREVIEWED → APPROVED → FREEZING → SETTLING → VERIFYING → COMPLETED / FAILED / ROLLED_BACK`
禁止只改 `season-id` / 配置即视为换季。永久层与赛季层物理隔离。

### C-011 不依赖全服删档

任何经济失衡不得以全服删档、回档、私下改库作为常规续命手段。必须通过参数调优、定向冻结、补偿事务修复。

### C-012 现实付费隔离

`support_credit`（现实付费积分）为独立账本，物理隔离于 `gold/merit/starlight`。禁止：
`support_credit → gold/merit/starlight/装备/材料/保护石/幸运符/经验/体力/掉率/赛季调谐/排行战力`

### C-013 自动系统只能冻结，不能自动改价

风控/反作弊自动动作仅限「冻结异常来源、限流、告警」。禁止自动修改价格、掉率、额度、税率。

### C-014 多服前置

启用 Velocity 多服 / 多 Paper 节点前，必须具备：
`Session Lease + 邮箱领取租约 + Transactional Outbox + 全局 Advisory Lock 迁移`。内存锁不得称为跨节点锁。

### C-015 章节与转数强绑定

`MAX_ASCENSION=3`, `LOCAL_LEVEL_CAP=30`, 有效等级 `1-120` 四段式：
0转 1-30 / 1转 31-60 / 2转 61-90 / 3转 91-120
章节推进由 `rpg_chapter_state` 唯一决定，禁止自动按日期开放、跳章、回退。

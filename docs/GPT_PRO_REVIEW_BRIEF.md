# 希维塔大陆：GPT Pro 深度审计交接

更新时间：2026-08-22。本文描述当前源码能证明什么、还不能证明什么。不要把“实现存在”“单元测试通过”“服务器能启动”误写成正式服已完成。

## 一句话定位

这是面向 Minecraft Java Edition 26.2、Paper 与 Java 25 的原创生存 RPG。目标不是替换原版生存，而是让原版采集、建造、探索、怪物、床、领地和玩家社区持续为职业、装备、副本、经济与长期构筑供给内容。

## 当前技术基线

- 25 个自研插件、15 个成熟社区插件；玩法状态坚持唯一所有权，社区插件只承担权限、认证、皮肤、建筑保护、领地、地图、NPC、剧情、宠物实体与表现层。
- 角色、财富、装备、技能、市场、副本、事件和奖励以服务端事务、签名 PDC、唯一流水及幂等恢复为边界。
- Paper 只监听回环后端，LAN/公网经 HAProxy 与 PROXY v2 接入；公网通过 FRP 回环端口转发。
- Java 25，Xmx 5 GiB；systemd `MemoryHigh=6 GiB`、`MemoryMax=7 GiB`、`MemorySwapMax=0`。预生成、地图渲染、备份、构建必须串行。
- 任意纯原版 26.2 客户端可加入；资源包增强 HUD、图标和模型，拒绝资源包时必须可用原版图标、粒子、声音和文字降级。

## 经济设计核心

1. 玩家之间交易只转移金币并收税，不凭空创造货币。
2. 自动农场材料可用于建筑与玩家交易，但系统不提供无限固定价回收；资源委托还要求绑定劳作证明、账号游玩时长、每日轮换和个人额度。
3. 星辉可肝取也可由管理员以唯一流水发放，只购买同上限养成保护物、限时便利和永久外观，不出售独占战力。
4. 金币主要从主动狩猎、副本、探索和受控委托产生；锻造、精炼、突破、变异、解绑、市场税、社群建设和便利服务负责回收。
5. 任何平衡结论必须基于至少完整七日窗口；目标是成熟期活跃金币周增 0–1%、七日回收/产出比 0.95–1.05。

## 关键架构边界

- `RpgCore`：角色、体力、财富、市场/商人账本、技能和副本入场预留的数据库边界。
- `RpgItems`：装备身份与签名唯一来源；Lore、模型和第三方 NBT 都不是权威数据。
- `RpgCombat`：职业、装备、处决、Boss/PvP 缩放的最终伤害总线。
- `RpgDungeons`：实例、队伍、波次和参与者奖励唯一所有者。
- `RpgMobs`：动态等级、词缀、掉落与模型分配唯一所有者；BetterModel 只做外壳。
- `RpgMarket`：高价值交易、税、唯一索引与邮箱；禁止通用面对面交易绕过审计。
- `RpgGuide`：菜单和引导投影，不复制任何玩法数据库。
- `RpgAiNpc`：只读解释与建议，无工具、无写服务；外部模型失败必须降级本地知识。

## 已知最高风险

1. 多人容量只有单人/空服基线，尚无 30/50/70/100 人阶梯压测证据。
2. PostgreSQL、节点 lease、奖励 journal、邮箱和市场尚缺组合式故障注入。
3. 赛季轮换记录存在，但正式赛季结算事务未完成，不能只改 `season_id`。
4. 内容广度已达 Alpha，长期深度仍不足：高阶被动、手工副本机关、更多世界事件和季度内容生产能力是主要缺口。
5. HUD、资源包、NPC、技能特效和模型仍需要多分辨率、多语言真人视觉验收。
6. 可选服务仍有少量跨插件生命周期缓存风险；应继续改为启用时动态解析，视觉缺失不得影响战斗数值。

## GPT Pro 应重点回答的问题

1. 从玩家首小时、首周、首月、三个月四个阶段，哪里会迷路、卡进度或提前毕业？
2. 六职业和 42 技能是否形成明确且可持续的职责/构筑差异？哪些技能只是视觉不同但决策相同？
3. 装备 0–8 槽、精炼、突破、变异、借技和传承是否形成可理解的长期循环，还是堆叠了过多随机层？
4. 哪些货币来源可被自动化、组队对刷、小号、市场搬运或跨系统兑换套利？
5. 金币/功勋/星辉的水龙头与回收口，在开荒、成熟、赛季末分别是否闭合？
6. RPG 与原版生存是否互相供给，还是玩家最终会被迫只刷副本？
7. 副本、血月、连猎、宠物、社群和领地如何共同形成重复可玩的社交动机？
8. 事务、幂等、签名、邮箱、节点租约和跨插件生命周期还存在哪些数据丢失/复制/半提交路径？
9. 在 15 GiB 主机、Paper Xmx 5 GiB 下，哪些任务、实体、区块、模型或数据库路径最可能造成卡顿或 OOM？
10. 请给出按 P0/P1/P2 排序的整改计划，并明确每项的验收方法，而不是只提出概念建议。

- 区分“源码实现”“自动测试”“真实运行”“真人客户端验收”四种证据。
- 每个结论引用具体文件与符号，不凭 README 宣称完成。
- 先输出系统关系图和玩家循环，再输出风险；不要逐插件机械复述。

# 经济压力模型

[English specification](README.md)

现在 `run.py` 已从场景占位脚本改为可执行的逐日模型：S01–S14 运行实际配置驱动的行为仿真，S15 在建立模型前拒绝现实支持积分连接游戏财富。模型只读仓库文件，不访问生产数据库、不改价格、不自动调整掉率。

## 运行

```bash
python3 -m unittest discover -s tools/economy-sim -p 'test_*.py'
python3 tools/economy-sim/run.py --output build/economy-sim/simulation.json
```

Python 3.10+，依赖 `PyYAML==6.0.3`。默认运行全部15场景；可用 `--only S05 S10 S13 S15` 筛选。`--seed` 控制随机种子。`--expected-inputs` 指向上一次报告时，输入SHA256不一致就提前失败。成功运行原子替换指定输出，失败保留已有报告。

## 已实现的机制

模型直接读取7个插件的真实配置，使用整数分计算金币、整数单位计算功勋和星辉。读取内容包括来源奖励/上限、委托活跃证据、掉落概率/保底、锻造费用、精炼费用、商城消耗、市场税费/期限、兑换与管理员配额。木质基础装备的最低催化成功率系数从当前 `ForgeRules.java` 提取，代码结构变化时要求重新审查。

模型逐日执行十类玩家的活动选择，记录金币产消、材料积累、装备创建/退出、市场转移、挂牌老化、兑换以及财富分布。资金守恒、装备身份守恒、真实配额与支持积分隔离均为运行门禁。S07通过限制其他成交来实现指定卖方占比，不凭空制造库存或买家资金；S12重新分配预期周活动小时，同时记录实际周末占比。

S12 支持周末占比为 0；末尾不足一周的日历边界和随机出勤会影响实际占比。单人单日超过 24 小时的目标被截断并明确告警，实际占比与目标相差超过 3 个百分点也会单独标记，不以虚构在线时间补齐目标。空场景集、非法人口权重、非整数交易金额或管理员发放量都会使模型失败。

价格、奖励与额度来自实际配置；在线时长、行动频率、市场购买意愿和内容空窗流失率属于 `behaviors.v1.yaml` 中明示的**未校准行为假设**。两类输入分别列入报告，均有完整SHA256。

## 输出怎么理解

报告包含周金币增长、按活跃玩家日计算的净增长、Sink/Faucet、兑换释放金币占比、装备产消比、市场成交/过期、库存P50/P90/最老龄、财富基尼和前1%占比。分母为零的比率写 `null`。兑换无正价值闭环通过严格正参考向量证书校验，不能增值的每一条边同时覆盖混合币种成本。

没有真实观测摘要时一律输出 `NEEDS_TUNING`。可用 `--ledger-summary` 比较带来源说明、相同人数/天数的观测指标，但不会自动拟合参数。离线模型检查通过不代表Java或数据库运行正确，也不代表已适合长期运营。

模型尚不执行Paper、真实JDBC并发、完整成长与难度、体力/副本准入、全部收入和消耗、稀有度/词条/绑定的完整状态机。普通基础装备和催化材料假设可获得，装备退出按最低1份精华估算；这些限制会明显影响余额增长。因此应先用模型发现需要采样的变量，再结合七日真实数据与小规模玩家实验校准，不据模型数字直接改生产经济。
